# Subchange 002.2 — Criar schema relacional e RLS

## Objetivo

Criar a fundação relacional de projetos com propriedade por usuário e isolamento obrigatório no banco.

## Escopo aprovado

- Criar somente a tabela `public.projects`.
- Relacionar `owner_id` a `auth.users(id)`.
- Adicionar campos do briefing inicial, estados e timestamps.
- Usar exclusão lógica por `deleted_at`.
- Ativar RLS e políticas de proprietário para leitura, inserção, atualização e exclusão.
- Conceder acesso à Data API somente ao papel `authenticated`.
- Gerar tipos TypeScript após a aplicação da migração.
- Não criar usuários ou implementar telas de login.

## Critérios de aceite

- Migração versionada e registrada no Supabase.
- Chave estrangeira e coluna usada pela RLS possuem índice adequado.
- `anon` não possui privilégios sobre `projects`.
- Usuário autenticado só pode operar linhas cujo `owner_id` seja seu UID.
- Atualização não permite trocar o proprietário.
- Constraints rejeitam estados, níveis e tamanhos inválidos.
- Advisors de segurança e performance não apresentam erro relacionado à migração.
- Tipos TypeScript representam o schema remoto.
