# Padrões de código## Linguagem e tipos- TypeScript em modo estrito; evitar `any`.- Validar dados em toda fronteira externa.- Usar nomes de domínio em inglês no código e português na interface.- Representar estados com tipos discriminados, não combinações ambíguas de booleanos.## Organização- Dependências apontam da interface para aplicação e domínio, nunca do domínio para a interface.- Cada módulo expõe uma API pública pequena; imports internos entre módulos são proibidos.- Código server-only e client-only deve ser explicitamente separado.- Componentes de UI não acessam banco ou provedores diretamente.## Qualidade- Funções pequenas, coesas e testáveis.- Tratamento explícito de erros esperados; mensagens internas não vazam para o usuário.- Sem números mágicos, prompts soltos ou schemas duplicados.- Prompts, schemas e templates de exportação devem ser versionados.- Datas em UTC no armazenamento e no fuso do usuário na apresentação.## Interface e acessibilidade- HTML semântico, navegação por teclado e foco visível.- Labels e mensagens de erro ligados aos campos.- Contraste compatível com WCAG 2.2 AA.- Estados de carregamento, vazio, sucesso e erro para fluxos assíncronos.- Layout funcional a partir de 320 px e sem depender apenas de hover.## Revisão- Toda mudança deve referenciar sua especificação.- Sem código comentado, segredos, fixtures enganosas ou dependências sem justificativa.- Lint, checagem de tipos, testes e build devem passar antes da conclusão.
